MVP Feature Scope (What is in vs. out)To get a functional prototype running quickly, we must differentiate between the immediate core system and future scale enhancements.What is IN the MVP:Telemetry Collection: One ESP32 node reading core temperature, pressure, and ambient humidity.Local Ingestion: A single Jetson Nano acting as the master node to ingest and run anomaly predictions.Deterministic Thresholding + ML: A hybrid model that instantly alerts on hard safety boundaries (e.g., Pressure $> 6.5\text{ bar}$) while using a lightweight ML algorithm to track rapid rates of change.Basic Web Alert Dashboard: A local web page displaying real-time sensor charts that flashes red and sounds an alert if a safety threshold is breached.What is OUT of the MVP (Save for Post-MVP Scaling):4x Cluster Parallelization: Testing on a single Jetson Nano first prevents networking bottlenecks from stalling early progress.Solar/Battery Backup Integration: Run on standard wall/bench power initially before designing industrial power-interruption backups.GSM/SMS Fallback Module: Rely on local Wi-Fi/Ethernet alerts before adding cellular SMS notifications.Phase-by-Phase Execution PlanPhase 1: Hardware Sandbox (Week 1)Goal: Confirm your sensors don't lock up and data formats correctly.Action: Flash the FreeRTOS code provided in the previous step to your ESP32. Open your serial monitor and verify that your JSON payloads look exactly like this every 200ms:{"T_core": 24.50, "P": 1.0132, "H": 78.00, "T_amb": 28.20}Phase 2: Synthetic Data & Model Prototyping (Week 2)Goal: Create your data framework and train your anomaly detection script.Action: Because open-source Cameroonian factory telemetry is hard to find, write a Python script to synthesize 10,000 rows of normal rubber vulcanization data mixed with occasional explosive anomalies (sudden pressure/temp spikes). Use this data to train a lightweight machine learning model (like an Isolation Forest or Logistic Regression curve).Phase 3: Single-Node Ingestion (Week 3)Goal: Bridge the physical world with your edge intelligence.Action: Set up your primary Jetson Nano. Write a lightweight Python script on the Jetson that opens a socket or runs an MQTT broker to listen to the ESP32. Feed the incoming real-time JSON string straight into your trained predictive model.Phase 4: Cluster & Web Interface Deployment (Week 4)Goal: Scale your computation and visualize the safety matrix.Action: Spin up a lightweight web dashboard (using Python's Flask or Node-RED) hosted right on the Jetson Nano. Link your remaining three Jetson Nanos into a cluster to distribute data processing, ensuring your system handles multiple incoming ESP32 streams across an industrial floor without missing a beat.

💾 NODE 2: Storage Server (Database & Historical Data)
IP Address: 192.168.1.26
Primary Role: PostgreSQL database, time-series storage, data backup

Installation Script
bash
#!/bin/bash
# ============================================
# NODE 2: STORAGE SERVER SETUP
# ============================================

echo "============================================"
echo "NODE 2: STORAGE SERVER - JETSON NANO"
echo "============================================"

# 1. System Update
sudo apt update && sudo apt upgrade -y

# 2. Install PostgreSQL and Tools
sudo apt install -y \
    postgresql postgresql-contrib \
    timescaledb-postgresql-10 \
    redis-server \
    nfs-kernel-server \
    python3-pip

# 3. Configure PostgreSQL with TimescaleDB
sudo systemctl start postgresql
sudo -u postgres psql << EOF
CREATE USER industrial_user WITH PASSWORD 'secure_password';
CREATE DATABASE industrial_db OWNER industrial_user;
\c industrial_db
CREATE EXTENSION IF NOT EXISTS timescaledb;
EOF

# 4. Create Database Schema
sudo -u postgres psql -d industrial_db << 'EOF'
CREATE TABLE sensor_data (
    time TIMESTAMPTZ NOT NULL,
    node_id TEXT NOT NULL,
    temperature FLOAT,
    pressure FLOAT,
    humidity FLOAT,
    raw_data JSONB
);

SELECT create_hypertable('sensor_data', 'time');

CREATE TABLE model_versions (
    id SERIAL PRIMARY KEY,
    version TEXT,
    accuracy FLOAT,
    trained_at TIMESTAMPTZ,
    model_path TEXT
);

CREATE TABLE alerts (
    id SERIAL PRIMARY KEY,
    alert_time TIMESTAMPTZ,
    alert_type TEXT,
    severity TEXT,
    message TEXT,
    acknowledged BOOLEAN DEFAULT FALSE
);
EOF

# 5. Setup NFS Share for Cluster
sudo mkdir -p /mnt/cluster_storage
sudo chown nobody:nogroup /mnt/cluster_storage
sudo chmod 777 /mnt/cluster_storage

echo "/mnt/cluster_storage *(rw,sync,no_subtree_check)" | sudo tee -a /etc/exports
sudo exportfs -a

# 6. Configure Redis for Caching
sudo systemctl enable redis-server
sudo systemctl start redis-server

# 7. Create Backup Script
sudo tee /usr/local/bin/backup_db.sh << 'EOF'
#!/bin/bash
BACKUP_DIR="/mnt/cluster_storage/backups"
mkdir -p $BACKUP_DIR
pg_dump -U industrial_user -h localhost industrial_db > $BACKUP_DIR/db_backup_$(date +%Y%m%d).sql
find $BACKUP_DIR -name "*.sql" -mtime +30 -delete
EOF

sudo chmod +x /usr/local/bin/backup_db.sh

# Add to crontab (daily backup at 2AM)
(crontab -l 2>/dev/null; echo "0 2 * * * /usr/local/bin/backup_db.sh") | crontab -

echo "NODE 2 SETUP COMPLETE!"
