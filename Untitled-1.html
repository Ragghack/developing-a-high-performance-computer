🚀 Jetson Nano Edge AI Project

Complete Retrospective · Industrial Upgrade Path · Developer Guide

📋 Executive Summary

Successfully transformed an NVIDIA Jetson Nano Developer Kit into a production-ready edge computing platform with headless operation, MQTT-based sensor ingestion, and a lightweight statistical anomaly detection model — completely avoiding TensorFlow/PyTorch complexity.

✅ Headless SSH/VNC ✅ OpenCV 4.5.0 with CUDA ✅ MQTT Broker Active ✅ Anomaly Detection Model 📡 ESP32 + BMP280

Key Successes

  • Headless WiFi + SSH + VNC fully operational
  • OpenCV 4.5.0 compiled with CUDA (27 modules)
  • MQTT broker (Mosquitto) stable on port 1883
  • ESP32 + BMP280 data ingestion via MQTT
  • Lightweight anomaly detection with scikit-learn
  • Successful training on real sensor data (528 readings)
  • Model exports: real_anomaly_model.pkl + scaler
  • Docker-based environment bypassed dependency hell

❌ Major Failures & Root Causes

  • TensorFlow installation failed – ARM64 wheel missing, protobuf conflicts
  • PyTorch 404 errors – NVIDIA moved/retired wheel URLs
  • xrdp session crash – GNOME + NVIDIA driver incompatibility → fixed with Xfce
  • Mosquitto “active (exited)” – broken init script → replaced with native systemd
  • Illegal instruction (core dumped) – x86_64 pip wheels on ARM64 → used apt/Docker
  • OpenCV 4.10.0 CUDA compile error – missing cuda/std/tuple → downgraded to 4.5.0

🛠️ Remedies & Best Solutions

  • For ML: Abandoned TF/PyTorch → used scikit-learn + statistical methods
  • For dependencies: Use apt or Docker containers for ARM64 compatibility
  • For remote desktop: Xfce/LXDE + TigerVNC (not xrdp)
  • For MQTT: Native systemd service with clean config
  • For OpenCV: Version 4.5.0 (stable with CUDA 10.2)
  • For data logging: CSV via MQTT subscriber → robust and simple

🧠 Hindrances & How We Overcame Them

🔧 Technical Hindrances

  • ARM64 vs x86_64 package mismatch → Docker + apt repo
  • NVIDIA JetPack 4.6 end-of-life → locked to stable versions
  • Limited RAM (4GB) → expanded swap to 7.9GB
  • CUDA 10.2 / Python 3.6 constraints → used compatible wheels
  • Slow compilation → reduced swap, used -j2 build flag

📡 Sensor & Network Hindrances

  • WiFi adapter driver (MT7601U) → loaded via mt7601u kernel module
  • MQTT connection refused → cleared port 1883, used fuser -k
  • ESP32 I2C address (0x76 vs 0x77) → auto-scan + manual fallback

📘 Developer Guide: Setting Up a Jetson Nano for Edge AI

1.  Flash JetPack 4.6 (R32.7) using SDK Manager
2.  Headless setup: jumper J48, serial over USB, nmcli wifi
3.  Expand swap: fallocate -l 6G /swapfile
4.  Install dependencies: apt install build-essential cmake git
5.  OpenCV 4.5.0 + contrib: use -D CUDA_ARCH_BIN=5.3
6.  MQTT broker: systemd service with listener 1883 0.0.0.0
7.  Python stack: apt install python3-numpy scipy sklearn
8.  Sensor ingestion: ESP32 → MQTT → Python subscriber → CSV
9.  Anomaly detection: IsolationForest from sklearn
10. Avoid TensorFlow/PyTorch; use statistical/lightweight models
